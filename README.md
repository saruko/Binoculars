# Binoculars 投稿前チェックツール

日本語 | [English](README.en.md)

投稿前の原稿を手元で確認するためのツールです。文章の類似度の確認、修正案の作成、Binocularsスコアの計算ができます。[Binoculars](https://github.com/ahans30/Binoculars)（Hans et al., ICLR 2024）をもとに機能を追加したもので、元の開発者による公式版ではありません。

**使う前に知っておいてほしいこと**
- 商用の類似度チェックの代わりにはなりません。照合先にない文献（購読誌の本文、Webページなど）との一致は検出できず、値も比較できません。
- 類似度の値だけでは判断できません。転用のない文章でも値が出るので、一致箇所を確認してください（[結果の読み方](#結果の読み方)）。
- 言い換えの候補とフラッグは確認のための候補で、不正の証拠ではありません。
- BinocularsスコアをAI利用の有無の根拠にしないでください（[医学論文での性能](#医学論文での性能)）。

## 機能

| 機能 | 内容 | 使う場所 |
|---|---|---|
| 類似度チェック | PubMed抄録、PMC全文（CCライセンスのみ）、手元のPDFと照合し、一致箇所をPDFとHTMLのレポートにします | 「類似度チェック」タブ、`check` コマンド、GitHub Actions |
| 言い換えの候補 | 文の埋め込みと再評価で、表現を変えた文の候補を挙げます。類似度の値には含めません | 「類似度チェック」タブ、`check` コマンド |
| フラッグ | 不自然な語句、撤回論文の引用、文字の加工、表示と抽出の不一致、引用の重なりを示します | 同上 |
| 修正案 | 一致した文の対応方法と修正案をLLMで作り、機械的に検査します。既定ではこのPC内のLLMを使います | 「修正案」タブ |
| Binocularsスコア | 文章のスコアを計算します。AI利用の有無は判定しません | 「Binocularsスコア」タブ |

原稿の内容が外部に出るのは、外部のAPIや GitHub Actions を選んだときだけです（[データの扱い](#データの扱い)）。

## 必要な環境
- Windows と Python 3.14。CUDA 13.2 版の PyTorch は `start.bat` が入れます。
- DOCXの原稿ページの作成に Word を使います（なくても動きますが、[ページと行が原稿と一致しません](#レポート)）。
- 全件の照合先には、約100GBのディスクが必要です。ベースラインのダウンロードは別に約52GBあります。

このリポジトリの測定は、メインメモリ64GB、GPUメモリ16GB（GeForce RTX 5080）のPCで行いました。

## 起動方法
1. `start.bat` をダブルクリックします。
2. 初回は仮想環境の作成とライブラリのインストールが自動で実行されます。
3. 完了するとブラウザ（`http://127.0.0.1:7860`）が自動で開きます。

類似度チェックには、先に照合先を作る必要があります（[照合先の作り方](#照合先の作り方)）。

## 照合先の作り方
照合先のデータは配布していません（[含めていないデータ](#含めていないデータ)）。各自のPCで作ります。コマンドは仮想環境の Python で実行します。

### 1. モデルの取得
言い換え検索のモデルは、原稿を外部に出さないようにPC内のキャッシュからのみ読み込みます。先に取得してください。

```bash
venv\Scripts\hf.exe download BAAI/bge-m3
```

```bash
venv\Scripts\hf.exe download Qwen/Qwen2.5-1.5B
```

### 2. 登録と索引の作成

```bash
venv\Scripts\python.exe -m simcheck add-pubmed
venv\Scripts\python.exe -m simcheck build-corpus corpus/queries.txt
venv\Scripts\python.exe -m simcheck add-library "PDFのフォルダ"
venv\Scripts\python.exe -m simcheck update-integrity
venv\Scripts\python.exe -m simcheck compact
venv\Scripts\python.exe -m simcheck index-citations
venv\Scripts\python.exe -m simcheck index-semantic
venv\Scripts\python.exe -m simcheck index-semantic --pubmed
venv\Scripts\python.exe -m simcheck index-semantic --add-matching "自分の分野の正規表現"
```

- 全件が不要なら、`add-pubmed` の代わりに `add-pubmed --first 番号 --last 番号` か `build-corpus` で範囲を絞れます。
- `corpus/queries.txt` の検索式は例なので、自分の分野に書き換えてください。
- `--add-matching` は、言い換え検索の対象に加える分野を題名か雑誌名で選びます。下記の評価では眼科とアレルギーの語（`ophthalm|ocular|\beye|retina|retinal|retinopath|cornea|corneal|glaucoma|cataract|uveitis|macula|myopi|conjunctiv|keratitis|keratoconus|vitre|optic nerve|allergic rhinitis|pollinosis|hay fever`）を使いました。
- `evaluation/` の結果の数値は、測定時の照合先での値です。

### コマンドの一覧

| コマンド | 内容 |
|---|---|
| `add-pubmed` | PubMedベースラインを登録します。`--first` と `--last` でファイル番号を指定でき、中断しても続きから再開します。空き容量が40GBを下回ると中断します |
| `add-pubmed-query "検索式"` | 検索式に合うPubMed抄録を登録します（1万件まで） |
| `add-pmc-query "検索式"` | 検索式に合うCCライセンスのPMC全文を登録します。1万件を超える検索は出版月で分けて取得します |
| `build-corpus ファイル` | 検索式を並べたファイル（`corpus/` を参照）から、まとめて登録します |
| `add-library "フォルダ"` | フォルダ内のPDFを登録します。元のファイルには書き込みません。`--rebuild` で登録し直します。スキャンPDFは登録できません |
| `update-integrity` | 不自然な語句のリストと撤回データを取得します。撤回データは平日に毎日更新されるので、確認の前に実行してください |
| `compact` | 指紋の索引を1つに統合します。ベースラインを大量に登録した後に実行してください |
| `index-citations` | 引用の重なりの確認に使う一覧を作ります。文献を増やしたら再実行してください |
| `index-semantic` | 手元のPDFの言い換え検索用索引を作ります。PDFを登録し直したら再実行してください |
| `index-semantic --pubmed` | PubMed抄録の言い換え検索用索引を作ります。件数は `--max-docs` で指定します（既定は10万件で、先に登録した文献から選びます） |
| `index-semantic --add-matching "正規表現"` | 題名か雑誌名が合うPubMed抄録を言い換え検索用索引に加えます。先に `--pubmed` で索引を作ってください。途中の結果を `data/simcheck/semantic_pubmed/parts/` に残すので、中断しても続きから再開します |
| `index-semantic --add-pmc` | 登録済みのPMC全文を言い換え検索用索引に加えます。既定の手順には含めていません（[下記](#pmc全文を言い換え検索に加えるか)） |
| `stats` | 索引の状態を表示します |
| `check "文書"` | 文書を確認してレポートを作ります（[類似度チェック](#類似度チェック)） |

索引とレポートは `data/simcheck/` に保存します。索引には購読誌PDFの本文も含まれるので、共有しないでください。

### 容量と時間
全件（PubMed抄録約2,840万件、PMC全文約14万件、手元のPDF 665件）での値です。

| 項目 | 値 |
|---|---|
| データベース（文献本体と引用の一覧） | 約59GB |
| 統合後の指紋 | 約23GB |
| 言い換えの索引（641万文） | 約7GB |
| 言い換えの途中結果（再開と追加に使用） | 約13GB |
| 約7,000語の原稿の確認 | 言い換え検索なしで約14秒、ありで約20秒（読み込みに初回はさらに約20秒） |

### PMC全文を言い換え検索に加えるか
既定の言い換え検索は、手元のPDFと索引を作ったPubMed抄録だけが対象で、PMC本文は対象外です。`--add-pmc` で加えられますが、代償が大きいので既定にはしていません。

| 項目 | 今の索引（641万文） | PMC全文を追加（2,804万文） |
|---|---:|---:|
| PMC本文の強い言い換えの検出 | 0% | 94.0% |
| PMC本文の軽い推敲の検出 | 0% | 50.0% |
| PubMed由来の強い言い換えの検出 | 97.9% | 95.8% |
| 転用のない文章の候補（1,000語あたり） | 2.58 | 3.53 |
| 索引の大きさ | 約7GB | 約29GB |
| 途中結果 | 約13GB | 約55GB |
| 確認時のメモリのピーク | 約15.5GB | 約38.4GB |

**`--add-pmc` は既定の索引 `data/simcheck/semantic_pubmed/` を置き換えます。** 残しておきたい場合は、先にフォルダごとコピーしてください。詳細は [評価結果](evaluation/detection/results.md) を参照してください。

## 類似度チェック
「類似度チェック」タブか、次のコマンドで確認します。PDF、DOCX、TXTを指定できます。

```bash
venv\Scripts\python.exe -m simcheck check "文書"
```

| 画面の項目 | コマンドの引数 | 既定 |
|---|---|---|
| 参考文献を除外 | `--include-references` で含める | 除外 |
| 引用符内を除外 | `--include-quotes` で含める | 除外 |
| 方法セクションを除外 | `--exclude-methods` | 含める |
| プレプリントを除外 | `--exclude-preprints` | 含める |
| 定型表現を除外 | `--exclude-common` | 含める |
| 一致とみなす最小語数 | `--min-words` | 8語 |
| 言い換えも確認 | `--no-semantic` で止める | 確認する |
| 言い換えの閾値 | `--semantic-threshold` | 0.85 |
| 除外する出典ID | `--exclude-id`（複数指定可） | なし |
| なし | `--triage` | 使わない |

`--triage` は、一致箇所を定型句と要確認に Gemini で仕分けます。**一致箇所の原稿の文章と出典の題名が Google に送られます。** 環境変数 `GEMINI_API_KEY` が未設定なら仕分けをしません。

### レポート
コマンドでは、`data/simcheck/reports/` に保存します（`--out` で変更できます）。

- **PDF**: 表紙、概要、出典一覧、原稿の各ページ、言い換えの候補の順にまとめます。原稿ページでは一致を赤、除外範囲を灰色、言い換えの候補を点線の下線で示し、左余白に出典番号を出します。出典の本文は載せません。
- **HTML**: 原稿と出典の本文を並べて比較できます。購読誌PDFの本文を含むので、共有しないでください。
- DOCXはWordでPDFに変換して原稿ページを作ります。作業用のコピーを使うので、元のファイルは変更しません。Wordを使えない場合は本文だけを組み直すので、ページと行は原稿と一致しません。

### 結果の読み方
- 類似度は、確認対象の語数に対する一致語数の割合です。語数は日本語2.5文字を1語として換算します。
- **照合先にない文献との一致は検出できません。** 低い値でも盗用がないことの証明にはなりません。
- 商用サービスとはデータベースも計算方法も異なるので、値は比較できません。投稿先での確認結果とは異なる場合があります。
- 転用がなくても定型句だけで値が出ます。照合先が大きいほど高くなります。PubMed全件では、AIの新規作成文の長文（平均848語）で平均8.0%、最大15.2%、抄録の長さ（平均296語）で平均14.2%、最大37.1%でした。短い文章では1文の一致で値が大きく動くので、値だけで判断せず一致箇所を確認してください。
- 一致とみなす最小語数の既定は8語です。7語以下にすると定型句の一致が急に増えます。
- 言い換えの既定の閾値は `0.85` です。再評価を使うときは類似度0.82以上の候補を利得で絞ります。再評価のモデルを読み込めないときは類似度0.85のみで判定し、その旨をレポートに書きます。
- 閾値を下げると検出は増えますが、実際の論文では同じ分野の無関係な文も多く挙がります。

### 検出の仕組み
1. PDF、DOCX、TXTから本文を取り出し、参考文献や引用などの除外範囲を決めます。
2. 文字の正規化（全角半角、合字、行末ハイフン、不可視文字、ラテン文字と同形のキリル文字とアルメニア文字、ラテン文字の単語に混ざったギリシャ文字など）をしてから、英語は単語、日本語は文字単位に分けます。
3. 指紋（winnowing）で候補文書を探し、トークン単位で位置を合わせて一致箇所を決めます。候補は全体の上位に加え、原稿の100語ごとの上位と、30文献以下にしかない指紋を共有する文献からも選びます。10語以上の連続した一致には必ず共通の指紋が残りますが、PubMed全件では候補に入らず見逃すことがあります（10語で約5%、8語で約2割）。
4. 複数の出典に一致する箇所は二重に数えません。定型表現の除外を選ぶと、多くの文献に共通する表現を一致からも分母からも除きます。
5. 言い換えは BAAI/bge-m3 の埋め込みで探し、英語の文は、出典を読ませると文の予測がどれだけ楽になるか（SCDG、Qwen2.5-1.5B）で絞ります。対象は手元のPDFと、索引を作ったPubMed抄録です。200万文を超えると、区画に分けた索引に切り替えて128区画だけを調べます（641万文で全件検索の約54倍の速さ、閾値0.82以上に届く文の取りこぼしは0〜3.3%）。英語の文からは日本語のPDFも探します。

### フラッグ
どれも類似度の値には含めません。

- **不自然な語句**: 言い換えツールの痕跡として知られる語句を、[Problematic Paper Screener](https://dbrech.irit.fr/pls/apex/f?p=9999:5) のリストと照合します。参考文献は対象外です。2種類以上の一致でフラッグにし、1種類は注記に留めます。
- **撤回論文の引用**: 参考文献を [Retraction Watch](https://gitlab.com/crossref/retraction-watch-data) のデータとDOI、PMID、題名で照合します。撤回と懸念表明を分けて示し、訂正だけの論文と撤回が取り消された論文は示しません。題名だけの一致は別の項目にします。
- **文字の加工**: 不可視文字、多数のソフトハイフン、ラテン文字の単語に混ざった形の似た文字、透明文字などを示します。
- **表示と抽出の不一致**: PDFの見た目と抽出した文字列が大きく違うページを示します。最大4ページを描画して、このPC内のOCR（RapidOCR）で読み取って比べます。
- **引用の重なり**: 同じ文献との共通の参考文献が10件以上で、共通の割合が80%以上、並び順の一致が70%以上のときに示します。`index-citations` を実行した文献が対象です。

不自然な語句、表示と抽出の不一致、引用の重なりの検出率は確認していません。一致しなくても問題がないことの証明にはなりません。

### GitHub Actions で動かす
[手順書](docs/github-actions.md) を参照してください。**このリポジトリは公開なので、原稿を置かないでください。** Actions を使うときは、別の非公開リポジトリを作ります。原稿の全文が GitHub に保存されます。

## 修正案
一致した文ごとに、対応方法（引用を追加、引用符と引用、書き直し）の提案と修正案を作ります。文に数値がなく、同じ表現が照合先の多くの文献に現れる場合だけ、定型句の可能性を示します。この判定はLLMに任せません。LLMに任せると、結果の数値を含む文にも「引用不要」と答えることがあったためです。本文は自動で変更せず、著者が選んだ対応をコメントとして付けたWordのコピーを `data/simcheck/revisions/` に保存します。

**書き直しても、出典の内容を使っている場合は引用が必要です。** 類似度を下げることを目的にせず、1件ずつ内容を確認してください。採用した文はAIによる編集にあたるので、投稿先の規定に沿って申告してください。

### 使い方
1. LLMの接続先を用意します（下の表）。
2. 「修正案」タブでDOCXと接続先を指定して作成します。
3. 1文ずつ案を確認し、必要なら編集して対応を選びます。
4. 「Wordに書き出す」でコメント付きのコピーを作ります。元のファイルは変更しません。

### 接続先

| 接続先 | 既定のURL | 準備 |
|---|---|---|
| LM Studio | `http://127.0.0.1:1234/v1` | モデルを読み込み、サーバーを起動します |
| Strata（Qwen3.8-Flash-Next など） | `http://127.0.0.1:8080/v1` | `strata launch` で起動します。キーを設定した場合は `STRATA_API_KEY` にも設定します |
| llama.cpp | `http://127.0.0.1:9931/v1` | `llama-server` を起動します。ポートが違うときはURLも変えます。キーを設定した場合は `LLAMA_API_KEY` にも設定します |
| Gemini API（外部に送信） | 変更不可 | 環境変数 `GEMINI_API_KEY` を設定します。既定のモデルは `gemini-3.8-flash` です |
| Claude API（外部に送信） | 変更不可 | 環境変数 `ANTHROPIC_API_KEY` を設定します。既定のモデルは `claude-opus-5-5` で、利用料がかかります |

- 想定しているローカルLLMは Gemma 4、Qwen3.5、DeepSeek、Qwen3.8-Flash-Next などです。品質を確認したモデルは [評価結果](evaluation/revise/results.md) に記載したものだけです。
- 接続を実機で確かめたのは LM Studio だけです。Strata、llama.cpp、Gemini API、Claude API は模擬応答のテストのみです。

### 外部のAPIを使うとき
**原稿の文と前後の文、出典の題名と抜粋が外部の事業者に送られます。** 未発表の原稿を送ってよいか、事業者のデータの扱いと投稿先の規定を確かめてから使ってください。

- 外部のAPIは、接続先を選び、送信に同意するチェックを入れたときだけ使えます。
- 手元のPDFが出典の文では、購読誌の本文を送らないよう、出典の抜粋を渡さず題名だけを渡します。そのため修正案の質が下がることがあります。
- APIキーは環境変数から読み、画面には入力しません。外部のAPIのURLは変更できません。
- ローカルの接続先に、このPCの外のURLは指定できません。
- Claude API では、安全機能で拒否されたときに別のモデルでやり直す機能（`fallbacks`）を使います。

### 案の検査
LLMの自己申告には頼らず、各案を次の項目で検査します。検査に通らなかった案も表示しますが、問題点を明記して後ろに並べます。

- 数値と文献番号が元の文と同じか
- 略語や用語が消えていないか
- 否定の表現の数が変わっていないか
- 元の文にない増減や比較の方向を表す語がないか
- 統計的有意性の表現が変わっていないか
- 元の文と同じ言語か（変わった案は表示しません）
- 元の文とまったく別の文になっていないか（bge-m3 の類似度、閾値 0.75）

照合先と一致が残る語数も参考として表示しますが、案の並び順には使いません。

**検査に通った案も、そのまま採用できません。** 公開抄録の文での確認では、検査に通った案45件のうち4件で意味がはっきり変わっていました（`One group` を `experimental group` にするなど）。事実の追加や、方法や対象の置き換えは検査では検出できないので、採用する前に必ず著者が内容を確認してください。対象は完全一致の文だけで、言い換えの候補は含みません。詳細は [評価結果](evaluation/revise/results.md) を参照してください。

## Binocularsスコア

### モデルの指定ルール
- **必須条件**: Observer（Base）と Performer（Instruct）は**同一ファミリー・同一語彙（トークナイザー）**である必要があります（例: `Qwen/Qwen2.5-1.5B` と `Qwen/Qwen2.5-1.5B-Instruct`）。語彙が異なる場合はロード時にエラーになります。
- ローカルパスまたは Hugging Face モデルIDを指定してロードしてください。
- ローカルパスは Hugging Face 形式（`config.json` と `*.safetensors` を含むフォルダ）である必要があります。LM Studio の GGUF ファイルは読み込めません。
- モデルのリポジトリに含まれるコードは実行しません（`trust_remote_code` は使いません）。独自のコードが必要なモデルは読み込めず、エラーになります。

### スコアの読み方
- スコアは log PPL を log Cross-PPL で割った値で、低いほどAI生成文に近い傾向があります。
- 「AI生成」や「人間作成」の判定と閾値は表示しません。評価の結果、どの閾値でも実用になる判定ができなかったためです。
- 長い文書は512トークンごとに分割して全体を評価し、区間別のスコアも表示します。
- 画面右側で、各トークンがモデルの予測にどれだけ沿っていたかを色で表示します。緑は予測通り、赤は予想外の語です。AIか人間かを示すものではありません。

### 医学論文での性能
**このスコアを、AI利用の有無の根拠にしないでください。** Qwen2.5-1.5B の組み合わせを英語の医学論文の文章で評価したところ、事前に定めた基準を満たさず、閾値の調整では解決できませんでした。

| 項目 | 結果 |
|---|---|
| AUC（AIの新規作成文、抄録の長さ） | 0.729（95%信頼区間 0.683〜0.774） |
| 論文の閾値0.9015（Falcon向け）で判定した場合 | 人間の抄録の5.0%をAIと誤判定し、AI文の22.6%を検出 |
| 閾値0.916（校正用の偽陽性率5%）での日本の所属の誤判定 | 10.0%（日本以外は3.3〜5.0%、件数が少なく差は確定できない） |
| AIが推敲した文章のAUC | 0.541（ほぼ判別できない） |
| 長文のAUC | 0.497（判別できない） |

スコアが高くてもAIを使っていないことの根拠にはならず、低くてもAIを使ったことの根拠にはなりません。日本語の文章は評価していません。詳細は [評価結果](evaluation/ai_threshold/results.md) を参照してください。

## 評価結果
どれも測定時の条件での値で、実際の原稿での性能を保証するものではありません。

| 対象 | 主な結果（PubMed全件） | 詳細 |
|---|---|---|
| 類似度の検出率（合成原稿） | そのままの転用は8語で76〜81%、10語で約95%、12語で約98%、15語以上でほぼ100%。5語ごとに語を編集すると指紋が残らず、ほとんど検出できません | [results.md](evaluation/detection/results.md) |
| 言い換えの候補（合成原稿） | 強い言い換えの82〜98%を候補に挙げられます。日本語からの英訳は64〜86%で、値が定まっていません。転用のない文章でも1,000語あたり1〜3件の候補が出ます | [results.md](evaluation/detection/results.md) |
| 不自然な語句と撤回論文 | 誤検出の確認結果です | [results.md](evaluation/integrity/results.md) |
| 修正案 | 検査に通った案の品質の確認結果です | [results.md](evaluation/revise/results.md) |
| Binocularsスコア | 実用になる閾値はありませんでした | [results.md](evaluation/ai_threshold/results.md) |

## データの扱い

| 使うもの | 外部に送るもの | 送り先 |
|---|---|---|
| 類似度チェック（`--triage` なし） | なし | — |
| `check --triage` | 一致箇所の原稿の文章、出典の題名 | Google |
| 修正案（LM Studio、Strata、llama.cpp） | なし | — |
| 修正案（Gemini API、Claude API） | 原稿の文と前後の文、出典の題名と抜粋（手元のPDFの抜粋を除く） | Google、Anthropic |
| GitHub Actions | 原稿の全文、一致箇所（Geminiのキーを設定した場合） | GitHub、Google（[手順書](docs/github-actions.md)） |
| 照合先の登録と更新 | 検索式（原稿の内容は含みません） | NCBI など各データの提供元 |
| モデルの取得 | モデルID（原稿の内容は含みません） | Hugging Face |

- 語句リストにはライセンスの記載がありません。`data/integrity/` のデータを他の人に配布する場合は、先に提供元に確認してください。
- 画面からアップロードした文書は、Gradio がPC内の一時フォルダにコピーします。

### 含めていないデータ
`data/` はリポジトリに含めません。

| データ | 含めない理由 |
|---|---|
| 手元のPDFの本文（`data/simcheck/docs.sqlite` の一部） | 購読誌の本文です。文字列として取り出しても著作権はなくなりません |
| PubMed抄録 | 配布には [NLMの条件](https://www.nlm.nih.gov/databases/download/terms_and_conditions.html)（出典の表示、最新版の維持またはその旨の明記）があり、抄録自体の著作権は出版社や著者にある場合があります。各自で取得できます |
| PMC全文 | 論文ごとにCCライセンスの条件が異なります。各自で取得できます |
| 評価用のデータ（`data/detection_eval/`、`data/ai_threshold/`） | 購読誌PDFの抜粋を含みます |
| 不自然な語句のリスト（`data/integrity/`） | ライセンスの記載がありません |
| 指紋と埋め込みの索引 | 本文がないと一致箇所を示せません。数十GBあり、GitHubのファイルサイズの上限も超えます |

PubMedのデータの提供元は U.S. National Library of Medicine です。このリポジトリはNLMの承認を受けたものではありません。

## 開発

### テスト
```bash
venv\Scripts\python.exe -m pytest tests
```

### 依存パッケージの更新
`start.bat` は起動のたびに、PyTorch を CUDA 13.2 版の配布元（`--index-url`）から、残りを PyPI から `constraints.txt` の版で入れます。PyTorch は `--no-deps` で入れます（配布元に `constraints.txt` の版がない依存パッケージがあるため）。`requirements.txt` に配布元を書いていないのは、`--extra-index-url` にすると、同じ名前の PyPI のパッケージと比べて版の高い方が入るためです。

版を更新するときは、版を上げて `pip-audit` とテストを通してから `constraints.txt` を置き換えてください。

### 既知の未修正の脆弱性
gradio（最新の 6.31.0 も）が `pillow<13.0` を要求するため、Pillow は修正版の 13.0.0 に上げられず 12.x が入ります（同梱の libopenjp2 のヒープオーバーフローなど）。gradio が Pillow 13 に対応するまで、信頼できない画像・PDF は読み込ませないでください。
